# AI-Enhanced Intrusion Detection System

Machine-learning-based Network Intrusion Detection System (NIDS) built on the
**NSL-KDD** dataset. The system classifies network traffic records as either
normal or one of four attack categories: **DoS**, **Probe**, **R2L** (Remote
to Local) and **U2R** (User to Root).

## Project Structure

```
├── notebooks/

├── reports/             Evaluation report + confusion matrix (generated by evaluate.py)

│   ├── train.py         Trains & compares Logistic Regression / Decision Tree / Random Forest
│   ├── evaluate.py      Scores the best model on the test set, saves report + confusion matrix
│   └── predict.py       Demo "real-time" scoring of new traffic records
├── requirements.txt
└── README.md
```

## Dataset

The [NSL-KDD dataset](https://www.unb.ca/cic/datasets/nsl.html) is an
improved version of the original KDD'99 dataset, with duplicate records
removed and a more balanced difficulty distribution. Each record has 41
traffic features (e.g. `duration`, `protocol_type`, `src_bytes`,
`same_srv_rate`, ...) plus a label naming the specific attack (or `normal`)
and a difficulty score. This project groups the ~39 specific attack labels
into 4 standard categories (DoS, Probe, R2L, U2R) plus `normal`.

Place `KDDTrain+.txt` and `KDDTest+.txt` in the `data/` folder (already done
if you're reading this from the provided project files).

## Usage

Run each stage of the pipeline from the project root:

```bash
# 1. Clean data, encode features, scale numerics
python src/preprocessing.py

# 2. Train & compare models, save the best one
python src/train.py

# 3. Evaluate the best model on the test set
python src/evaluate.py

# 4. Try real-time-style scoring on sample traffic
python src/predict.py
```

Or open `notebooks/IDS_EDA_and_Modeling.ipynb` in Jupyter to see the full
walkthrough with charts inline (also useful for screenshots in your project
report).

## Results (Random Forest, best model)

| Metric | Score |
|---|---|
| Test Accuracy | 0.75 |
| Test Macro F1 | 0.52 |

Performance is strong on `normal` and `DoS` traffic, and notably weaker on
`R2L`/`U2R` — this is a well-documented property of the NSL-KDD test set,
which deliberately includes attack sub-types absent from training to test
generalization. See `reports/evaluation_report.md` for the full
classification report and `reports/confusion_matrix.png` for the confusion
matrix.
